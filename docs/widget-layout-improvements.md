# 桌面挂件布局改进与验证

日期：2026-10-28。本次修改四类独立挂件的摆放、尺寸、布局与恢复，不修改实际桌面文件和图标位置。

## 使用方式

- 拖动挂件标题栏移动；边缘或四角调整大小。
- 靠近可见挂件或屏幕工作区边缘时吸附。默认间距为 16 个逻辑像素，吸附阈值为 8 个逻辑像素，按住 Alt 临时关闭。
- 对齐时在当前挂件表面高亮对应边缘或中心线；拖动时显示逻辑尺寸。当前没有跨窗口的全屏引导线覆盖层。
- 点击标题栏的“…”或右键空白区域，选择紧凑/标准/展开、锁定位置、始终置顶、撤销、找回或重置。编辑框保留原生文本右键菜单。
- 标题栏获得键盘焦点时可用方向键微调，Shift+方向键每次移动 10 个逻辑像素；Esc 取消正在进行的拖动。
- 设置中心 → 桌面挂件 → 挂件尺寸与位置，可调整尺寸、锁定和找回；可以保存一套四类挂件的布局并恢复。快照包含位置、尺寸、可见性、锁定与置顶状态，不包含桌面图标分类布局。
- “始终置顶”是普通窗口置顶设置，取消后恢复普通窗口层级。本次没有实现 Explorer 桌面层嵌入。

## 尺寸预设（逻辑像素）

| 类型 | 紧凑 | 标准 | 展开 |
| --- | --- | --- | --- |
| 日历 | 280×340 | 320×380 | 420×460 |
| 专注 | 280×240 | 320×320 | 380×400 |
| 备忘录 | 280×220 | 320×300 | 420×440 |
| 天气 | 260×150 | 320×180 | 380×240 |

日历日期格根据窗口剩余高度分配，六行月份也可完整显示；高度至少 420 时增加可滚动的当日安排。选中日期与真实今天使用不同样式。

专注挂件的圆环与文字随可用空间调整，横向窗口采用左右布局。最小窗口打开自定义时长时转为时间文字，保留输入、验证消息和操作按钮，避免挤压成小圆环。

备忘录的新建按钮移动到标题栏，正文获得完整编辑区，底部简化为保存状态和字数。天气根据高度选择左右或上下布局，长城市名截断并保留提示。

## 原生布局与恢复

新的布局记录保存显示器标识、逻辑尺寸和工作区内相对位置，同时保留旧物理坐标以兼容现有数据。恢复时根据可用显示器缩放、约束整个窗口，尽量避开任务栏；找不到原显示器时回落到可用屏幕。保留旧布局，用户不需要删除历史设置。

拖动使用 Windows 物理鼠标坐标进行计算，起点通过客户区坐标转换，以避免 IPC 延迟及不可见窗口边框造成偏差。缩放使用统一最小尺寸与工作区约束。移动和缩放保留一次可撤销状态。

## 验证结果

- 前端生产构建通过。
- Rust 桌面代码检查通过；Tauri 内嵌资源原生 Debug 构建通过，命令为 `tauri build --debug --no-bundle -- --offline`（使用项目 toolchain.ps1 环境）。
- 核心回归 12 项通过，包括新加入的负坐标屏幕边界、完整窗口约束、间距吸附、最小缩放和拖动边缘吸附测试。
- `npm run widgets:check` 通过 20 个尺寸案例，覆盖四类挂件、六行月历、240 分钟、自定义时长错误状态和菜单边界；浏览器测试使用离线 dist 资源和模拟天气，未访问真实天气 API。
- 已检查生成的日历、专注、备忘录、天气截图。图片与 JSON 结果位于 `docs/verification/widgets/`。

### 隔离 Windows 客户端实测

测试使用 `YZAI_SAFE_PREVIEW=1` 及工作区独立 `YZAI_TEST_DATA_DIR`。未启动剪贴板监听、日程调度或注册桌面菜单，未改动用户实际图标。测试客户端已退出。

| 操作 | 实测结果 |
| --- | --- |
| 快速拖动标题栏 | 成功移动并保存；修正了 IPC 延迟和客户区边框偏差 |
| 右下角缩小 | 从 320×320 缩小至约 288×281，正文随之重排并保存 |
| 锁定后再次拖动 | 位置维持 508,164，未发生误移动 |
| 退出并重新启动 | 尺寸、位置与锁定状态保持 |
| 与日历的间距吸附 | 日历 x=40、宽 320；专注吸附至 x=376，间距为 16 |
| 标准尺寸预设 | 原生尺寸恢复为 320×320 |
| 保存整套布局 | 生成四类挂件布局快照 |
| 找回专注挂件 | 从 376,164 移至当前屏幕预设位置 24,420 |
| 恢复整套布局 | 回到 376,164，尺寸保持 320×320，与保存快照一致 |

多显示器的不同 DPI、显示器热插拔、任务栏四个方向和全屏应用层级尚未完成实机矩阵验证。普通窗口置顶不等同于桌面层嵌入。

## 复验环境

`widgets:check` 需要可用的 Playwright 与 Chromium。默认使用本机 Codex runtime 的 Playwright，可通过 `PLAYWRIGHT_MODULE` 和 `WIDGET_CHROMIUM_PATH` 指定其他安装。脚本通过路由提供本地 dist 文件，避免依赖 localhost 访问权限；先执行 `npm run build`。此检查没有验证原生窗口移动与 Shell 行为。
